About Evidence Sources

Evidence Sources are ways ControlPlane can determine where you are or what you are doing. You enable Evidence Sources so that you can then create rules that define when to transition to a configured context.

ControlPlane currently supports the following evidence sources (matching the in-app registry on modern macOS / Tahoe):

  • Active Application: Monitors which application has focus
  • Active Context: Matches when a named ControlPlane context is already active (useful for stacking rules)
  • Attached Power Adapter: Detects which power adapter is attached to your Mac based on its serial number. Useful on portable Macs only
  • AudioOutput: Monitors which audio output device is in use. Could be headphones, internal speakers or whatever else is available on the system
  • Bluetooth: Connected and/or nearby bluetooth devices
  • Bonjour: Services and devices located on your local network
  • CoreLocation: Your current location. Enabling this (or Wi‑Fi) will prompt for Location Services.
  • DNS (DNS Parameters): Search domains and DNS server addresses from the current network configuration
  • Focus: Whether Focus is currently on or off via the public Intents Focus Status API (INFocusStatusCenter). The public API does not expose which named mode (Work, Sleep, …) is active — use Set Focus / Run Shortcut for named modes. macOS may prompt for Focus Status access (System Settings → Privacy & Security → Focus). ControlPlane refreshes on wake and polls as a fallback because Apple does not publish a Focus-change notification.
  • Host Availability: Whether a hostname or IP is reachable on the network, using Network.framework (TCP probe to port 443). Useful for “on the office LAN / VPN” style contexts.
  • FireWire: Connected FireWire devices — only registered when IOKit reports a FireWire controller. Unavailable on Apple Silicon and most modern Thunderbolt-only Macs; do not expect this evidence source on modern Mac hardware without FireWire.
  • IP (Assigned IP Address): Current IPv4 and IPv6 addresses assigned to your Mac (prefix-aware rules for both families)
  • Laptop Lid: Whether a portable Mac’s lid is open or closed
  • Light: Ambient light level from the hardware sensor via AppleLMUController. Often unavailable on modern Macs (especially Apple silicon), where that IOKit service is absent — ControlPlane hides this evidence source when the sensor is not present.
  • Monitor: Attached monitors by product name, plus display count rules (for example 2 or more displays, or 1 or more external displays) and an optional arrangement fingerprint of the current layout. Count and fingerprint use public NSScreen / CGDisplay APIs only — not private WindowServer interfaces. Useful for “at desk” contexts when a laptop is docked to external displays.
  • Mounted Volume: Whether a named volume is currently mounted
  • NetworkLink: Status of a network link, either up or down
  • Power: Monitors the source of power (battery or adapter), battery charge percent thresholds, and Low Power Mode on or off
  • Remote Desktop: Whether a Screen Sharing / Remote Desktop session is active
  • RunningApplication: Monitor running applications
  • Screen Lock: Whether the screen is locked or unlocked
  • ShellScript: Allows you to write your own evidence source based on any script
  • Sleep/Wake: Allows ControlPlane to react to sleep and wake events
  • TimeOfDay: Match a given time
  • USB: Monitor attached USB devices
  • WiFi: Connected or nearby WiFi access points. On modern macOS (Sonoma and later, including Tahoe), reading Wi‑Fi network names (SSID) and BSSID requires Location Services for ControlPlane. If Wi‑Fi rules stop matching, open System Settings > Privacy & Security > Location Services and allow ControlPlane.

Fragile notification-based sources

Screen Lock and Remote Desktop do not use public AppKit APIs for live state. They observe undocumented macOS distributed notifications:

  • Screen Lock: com.apple.screenIsLocked / com.apple.screenIsUnlocked
  • Remote Desktop: com.apple.remotedesktop.viewerNames (payload key ViewerNames)

Apple can rename or stop posting these notifications in any OS update. If rules based on these sources stop changing after an upgrade, check Console for ControlPlane messages about missing notifications, then prefer another evidence source (Power, Wi‑Fi, Active Application, Host Availability, etc.). Automated tests inject lock / viewer state and never rely on live distributed notifications in CI.

Until the first notification arrives after enabling the source, Screen Lock assumes unlocked and Remote Desktop assumes no viewer is connected. ControlPlane logs a warning if no notification arrives within about 90 seconds of start.
